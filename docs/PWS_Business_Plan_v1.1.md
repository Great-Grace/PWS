## 1. 서비스 개요

PWS는 **개인 맞춤형 체감날씨 예측** 앱으로, 온디바이스 머신러닝(퍼셉트론)이 사용자 피드백을 학습하여 기존 날씨 앱이 제공하지 못하는 **"나에게 맞는 체감온도"**를 예측합니다.

### 핵심 차별화

| 기존 날씨 앱 | PWS |
|---|---|
| 모든 사용자에게 동일한 체감온도 | 개인별 체감 예측 (BMI, 생활패턴, 피드백 학습) |
| 풍속 기반 고정 공식 (Wind Chill / Heat Index) | 11차원 피처 벡터 + 온디바이스 SGD 학습 |
| 날씨 정보 "표시" | 날씨 정보 "예측 + 행동 추천" |
| 미세먼지/UV 부가정보 | 시간대별 옷차림 + 준비물 추천 (유료) |

### 수익 모델 (듀얼 레버)

- **무료 유저:** 배너/네이티브 광고 수익
- **유료 구독 (₩3,900/월):** LLM 기반 고도화 분석 + 개인화 옷차림 추천

#### 날씨 API 비용 최적화

PWS는 **2단계 캐싱**으로 API 호출을 최소화합니다:
- 좌표 1km 그리드 반올림 → 같은 동네 유저 캐시 공유
- 30분 TTL → 동일 위치 반복 호출 차단
- **실효 API 호출:** 유저당 ~0.3~0.5회/일 (캐시 히트율 80%+)

> ⚠️ **[v1.1 보정] 초기 캐시 히트율 현실화**
> 80% 히트율은 유저가 특정 지역에 밀집된 경우(예: 서울 강남)에만 성립합니다.
> MAU 5,000 미만 초기 단계에서는 전국 분산으로 **히트율 40~50% 수준**이 현실적이며,
> 이 경우 OWM API 비용이 2배 증가합니다. 아래 비용표는 초기 단계에 보수적 수치를 반영했습니다.

### 2.2 유료 모델 — LLM API 비용 분석

#### 호출 구조

유료 유저 1명당 **1일 1회** LLM 호출 (당일 첫 앱 진입 시 생성, 이후 캐싱):

```
[입력 패키지]                    ~640 tokens
├── 시스템 프롬프트              ~200 tokens  (역할 + 출력 포맷 정의)
├── 가중치 해석 프로필            ~80 tokens   ("습도 민감, 추위에 약함...")
├── 당일 날씨 벡터 (3슬롯)       ~100 tokens  (temp/humidity/wind/tmrt/precip)
├── 퍼셉트론 예측값              ~60 tokens   (morning: 2.8, afternoon: 4.1, ...)
├── 생활 패턴 요약              ~100 tokens  (commute/work_env/exercise)
└── 데일리 이벤트               ~100 tokens  (사용자 자유 입력)

[출력]                          ~350 tokens
├── 하루 한 문장 요약
├── 3슬롯 옷차림 추천
├── 준비물 리스트
└── 이벤트 맞춤 팁
```

**총 토큰:** 입력 640 + 출력 350 = **~990 tokens/call**

> ⚠️ **[v1.1 보정] LLM 비용 방어 — 일별 캐싱 필수**
> 유저가 하루에 앱을 여러 번 열어도 동일 날짜의 LLM 결과를 재사용해야 합니다.
> `predictions` 테이블에 `llm_output` JSONB + `llm_generated_at DATE` 컬럼을 두어
> 같은 날 이미 생성된 결과는 DB에서 즉시 반환 (API 재호출 없음).
> 미구현 시 다회 진입 유저 비용이 3~4배 증가할 수 있습니다.

## 6. 제품-시장 적합성 (PMF) 리스크 및 대응

> **[v1.1 신규 섹션]** — 비용/수익 모델보다 더 중요한 PMF 검증 사항

### 6.1 기본 앱과의 경쟁

**리스크:** iOS/Android 기본 날씨 앱과의 경쟁. 사용자가 새로운 앱을 설치하고 매일 열도록 유인하는 것 자체가 진입 장벽입니다.

**대응 전략:**

| 전략 | 내용 |
|---|---|
| 즉각적 WOW 포인트 | 설치 첫날부터 기본 앱과 다른 체감값 보여주기 (초기 그룹 baseline 활용) |
| 아침 알림 습관화 | "오늘 아침 뭐 입을지 알려드려요" → 앱 진입 동기 부여 |
| 주간 리포트 | "지난 주 날씨 예측 정확도 87%" → 개인화 가치 가시화 |
| 위젯 지원 | 홈화면 위젯 → 앱 열지 않아도 체감온도 확인 가능 (세션 외 접점) |

### 6.2 콜드 스타트 이탈 문제

**리스크:** 퍼셉트론이 개인화되기 전(7~30회 피드백) 구간에서 예측값이 일반적이어서 이탈 발생. lock-in 효과가 작동하는 30회 이상 피드백 유저 비율이 낮으면 전환율도 낮아집니다.

**현실적 이탈 시나리오:**

```
설치 100명 →
  Day 3  이탈 30명 (앱 가치 미체감)  → 잔존 70명
  Day 7  이탈 20명 (습관화 실패)     → 잔존 50명
  Day 30 이탈 15명 (개인화 체감 전)  → 잔존 35명
  피드백 30회 달성 유저: ~20명 (20%)
  → 유료 전환 대상 모수: 20명
  → 5% 전환율 가정 시 실제 전환: 1명 (전체의 1%)
```

**이탈 방어 전략:**

| 구간 | 전략 |
|---|---|
| Day 1~3 | 온보딩 체험 — 그룹 baseline으로 "이미 맞아 보이는" 예측 제공 |
| Day 3~7 | 피드백 넛지 알림 "오늘 체감은 어떠셨나요? (30초면 충분)" |
| Day 7~30 | "당신의 예측이 X% 정확해지고 있어요" 진행률 시각화 |
| Day 30+ | 유료 기능 미리보기 노출 (프리미엄 옷차림 추천 샘플) |

### 6.3 ₩3,900/월의 가치 검증

**리스크:** 매일 같은 추천을 받는 느낌이 들거나, 계절이 지나면 옷차림 추천의 변동성이 낮아질 수 있습니다.

**대응 전략:**

- **무료 7일 체험** → 부담 없는 전환 유도
- **유료 기능 차별화 심화** — 단순 옷차림이 아닌 "오늘 낮에 코트 벗어도 돼요 (오후 2시 14°C)" 같은 시간별 행동 가이드
- **구독 유지 동기** — 매달 "나의 체감 리포트" (내가 가장 추위를 많이 느낀 날, 예측 정확도 추이)

## 10. BM 실행 로드맵

### Phase 1: MVP 출시 + 광고 수익화 (Month 1-3)

- 무료 앱 출시 (온디바이스 퍼셉트론)
- 배너 + 네이티브 광고 삽입 (AdMob)
- **콜드 스타트 이탈 방어 UX 구현** (Day 1~30 피드백 넛지)
- 목표: 3,000 MAU → 월 ₩270K 실질 수익 (마케팅비 후)

### Phase 2: 유료 구독 도입 (Month 4-6)

- 생활 패턴 입력 + 데일리 이벤트 기능
- Claude Haiku 4.5 Edge Function + **일별 LLM 캐싱**
- RevenueCat 인앱 결제 + 7일 무료 체험
- 목표: 5,000 MAU / 3% 전환 → 월 ₩469K

### Phase 3: 성장 + 최적화 (Month 7-12)

- ASO 최적화 + 바이럴 공유 기능 (내 체감 공유)
- 위젯 지원으로 체류 시간 및 DAU 개선
- 연간 구독 프로모션
- 목표: 10K~30K MAU / 5% 전환 → 월 ₩882K~2.97M

### Phase 4: 스케일 (Year 2)

- 데이터 기반 부가 수익 (익명화 인사이트 → 패션/리테일 B2B)
- 글로벌 확장 (일본, 동남아)
- 목표: 50K~100K MAU
